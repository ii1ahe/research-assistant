What differed, failed, or surprised me:

  On the developer machine the suite prints 356 passed with no skips, because
  it runs against a local PostgreSQL. Here 7 database tests skipped, so I dug
  into why:

  - `docker compose ps`: the postgres container is Up and healthy.
  - `docker compose logs postgres`: the server is ready and accepting
    connections.
  - `docker inspect research-assistant-postgres-1`: postgres is attached to
    the research-assistant_default network at 172.18.0.2.
  - From inside the app container, `postgres` resolves correctly to
    172.18.0.2, but a raw TCP connect to 172.18.0.2:5432 times out after
    10 s. DNS works; the TCP handshake never completes.

  So container-to-container traffic over the Docker bridge does not work in
  this environment. A GitHub Codespace runs Docker inside a container
  (Docker-in-Docker), and its bridge does not carry packets between sibling
  containers here. This is a property of the Codespace platform, not of the
  repository: the same compose path was exercised during Phase 8 development
  (the offline-guard docstring in tests/conftest.py even documents the
  database at 172.18.0.2 under compose), and on a normal Docker host the
  compose demo runs end to end.

  The run also took 7:15 for 14 tests, and the diagnosis explains that too:
  asyncpg's default connect timeout is 60 s, our connect call sets none
  (researcher/storage/postgres.py, create_pool), and 7 x 60 s ~ 420 s of the
  435.54 s total is the skipped tests waiting out their timeouts. That is a
  real finding: an unreachable database should fail fast, not hang for a
  minute per attempt.

Things the README didn't tell me:

  - Database tests skip (not fail) when PostgreSQL is not reachable. The
    contributor brief mentions it ("Seven tests skip if PostgreSQL isn't
    running. Expected, not a failure.") but the README does not — worth a
    line in its testing section.
  - The skipped-tests timeout above. A follow-up change can give
    PostgresStorage.connect an explicit timeout so bootstrap fails fast
    instead of waiting out asyncpg's 60 s default per attempt.
